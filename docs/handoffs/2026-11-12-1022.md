## 1. Where we are

This is a RAG training showcase built with Next.js 16, Drizzle and pgvector. It now runs **fully locally on oMLX** (`/Applications/oMLX.app`, at `http://localhost:8000/v1`):
- **BAAI/bge-m3** does the embeddings (1024-dim).
- **Qwen3-4B-Instruct-2507-4bit** does chat.
- No OpenAI key is used anywhere.

This session added an **`/agent` demo page**: a hand-written tool-calling loop with live SSE streaming. For every turn it shows each model call, the exact prompt sent, the tool calls and results, and a per-segment breakdown of context-window usage. Conversations are kept as **sessions** in Postgres, with context compaction: each earlier turn is re-sent as a one-sentence summary when that summary is shorter.

All features are implemented and were verified end to end (tsc, `bun run build`, curl SSE, browser). **Almost everything is still uncommitted.** Only the design spec is committed. Nothing is deployed. The dev server has been stopped.

## 4. Decisions & rationale

- **The agent loop is hand-written** against `/v1/chat/completions`, not AI SDK `stopWhen`, so the page can show the exact request of each step. Keep it that way; CLAUDE.md says so too.
- **Context segments are counted with oMLX `POST /tokenize`.** `overhead = prompt_tokens − sum(segments)`, so the segments always add up to the real usage.
- **Compaction uses a summary only when it is shorter** than request + answer. Summarizing always made short turns *larger* (62 vs. 42 tokens).
- **History is request + final answer only.** A turn's tool traffic is never re-sent.
- **Stored turns are the raw SSE event list** (`agent_runs.events` jsonb), replayed through the same `reduceTurn` that handles live turns. One rendering path for both.
- **Colors:**
  - read tools: amber
  - write tools: red (the user's request)
  - errors: grey dashed (keeps red for write tools)
  - earlier turns: pink `#ec4899`
  - summary step: slate
- **TTFT label:** it is driven by *new, uncached* prompt tokens, not total prompt size, because oMLX does prefix caching.
- **The session-level chart** shows each turn's *first* model call, which is its starting context.

## 6. Gotchas

- **A hook blocks inline SQL writes** (`psql -c "UPDATE…"`). Put data changes in a migration file and run `drizzle-kit migrate`. Read-only `select`s are fine.
- **Adding a NOT NULL column to a table that has rows:** generate it nullable, backfill, then `SET NOT NULL`. 0002 was edited by hand this way.
- **oMLX embedding models must be safetensors.** For bge-m3, the root `config.json` needed a separate download.
- **The oMLX API key** is in `~/.omlx/settings.json` under `auth.api_key`. `.env.local` uses it as `EMBEDDING_API_KEY`.
- **`bun dev` fails if an old next-server still holds port 3000.** Check with `lsof -ti tcp:3000`. Kill only the `next-server` PID: `lsof` also lists Chrome's network helper.
- **The 4B model is weak.** It sometimes calls `search_documents` again because a summary dropped details. That is expected, and it shows the cost of lossy compaction.
